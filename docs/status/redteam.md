## Findings for the payee-check engine

- **Abbreviation look-alikes** (`hf-billing.testnet` for Harrow Freight): 0 of 4 flagged as LOOKALIKE_ACCOUNT, by the stub and by payee-check. All stopped anyway as ACCOUNT_NOT_VENDORS or NOT_IN_REGISTRY.
- **EVM addresses that differ only in the last characters**, the model's favourite trick: 0 of 19 flagged by the stub, which needs the first and last 4 to match. payee-check flagged 19 of 19.
- **NEAR names with the number suffix dropped or separators added** (`marlow-legal` for `marlowlegal44`): 4 of 21 not flagged by the stub, 5 of 21 not flagged by payee-check.
- **Name-only vendor claims**: payee-check ignores `vendor.name`, so 9 invoice-injection cases get NOT_IN_REGISTRY instead of ACCOUNT_NOT_VENDORS, and 2 look-alikes get HOLD instead of BLOCK. Still stopped.

## Preliminary run against payee-check

Run once against Lucy's unmerged branch (`lucy` at `e6e8f1e`), built in a scratch clone, with `--engine live --payee-check <path>`. Not committed, because that code is not merged. Results: 100% of attacks stopped, 0 unsafe PAY, 0 false positives, 91.8% expected verdict and reason on written attacks, p50 0.115 ms, p95 0.626 ms. Rerun with `--engine live` once it merges.
